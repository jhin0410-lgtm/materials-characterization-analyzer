# Materials Characterization Analyzer 0.11.0

Release date: **2026-08-04**

## Scope

This release closes the post-0.10.0 validation and interoperability work as one coherent public boundary.

### User-facing additions

- `mca analyzer-readiness`: generates a versioned evidence snapshot for XRD, SEM, EDS, Raman, XPS, FTIR, TGA, DSC, TEM, and SAED.
- `mca build-handoff`: creates a portable checksum-bound characterization bundle from an explicit config.
- `mca validate-handoff`: independently revalidates bundle file identity, schemas, sample IDs, provenance coverage, join rules, and scientific closeout.
- Fail-closed TEM and SAED source-request, response-assessment, transfer-verification, candidate-registry, and external-validation intake workflows.

## Installed-command quickstart

The installed commands are included in the wheel. The readiness registry and example handoff config are repository-owned evidence/configuration files, not package data, so the following examples require a source checkout at the exact commit being audited.

```bash
mca --version

mca analyzer-readiness \
  --config case_studies/analyzer_readiness_registry/readiness_registry.json \
  --output outputs/analyzer-readiness

cp docs/handoff_build_config.example.json handoff_build_config.json
# Replace every placeholder path and declared evidence field with reviewed,
# checksum-bound values before running the builder.

mca build-handoff \
  --config handoff_build_config.json \
  --output outputs/portable-handoff

mca validate-handoff \
  --bundle outputs/portable-handoff \
  --output outputs/portable-handoff-validation
```

`mca build-handoff --help` and `mca validate-handoff --help` work from a wheel-only installation. Building a real bundle additionally requires user-supplied feature, context, evidence, and scientific-closeout files referenced by a completed config. The builder and validator package declared evidence only. They do not infer sample identity, establish physical-aliquot equivalence, or upgrade the scientific evidence level.

## Compatibility

- The public package remains Python 3.10+.
- Existing analyzer commands, feature columns, bundle schema `1.0`, filenames, and valid workflows remain supported.
- `materials-data-analyzer` integration remains file-based; no cross-repository internal import is introduced.
- Existing producer-specific RWGS, carbon, and NIST bundle exporters remain compatible with the generic bundle validator.

## Validation

The release workflow performs:

- full repository pytest execution;
- wheel and source-distribution construction;
- installed-wheel version and CLI smoke tests;
- installed `mca analyzer-readiness` execution from a source checkout containing the registry config;
- bundle builder and validator command exposure checks;
- release metadata consistency checks;
- SHA-256 inventory generation for distributions and readiness evidence.

## Scientific closeout

**Software validation: Supported.**

All ten analyzer families have packaged baseline workflows and public real-data diagnostic execution or method-suitability evidence.

**Scientific validation: bounded.**

- XRD, SEM, EDS, Raman, XPS, FTIR, TGA, and DSC remain `Diagnostic` for their current scientific claims.
- TEM independent in-domain segmentation performance remains `Inconclusive` pending an eligible independent Co3O4 TEM/HRTEM cohort.
- SAED crystallographic performance remains `Inconclusive` pending an eligible independent calibrated static-SAED cohort.
- Independent external-validation readiness: `0/10`.
- Engineering-decision readiness: `0/10`.

The release does not establish automatic phase, composition, chemical-state, functional-group, reaction, mechanism, morphology, segmentation-performance, crystallographic, causal, predictive, optimization, or engineering claims.

## External data boundary

No third-party raw dataset is redistributed with the release. Public workflows continue to retrieve authoritative sources at runtime, verify source identity and checksums, and keep external licences separate from the BSD-3-Clause software licence.
