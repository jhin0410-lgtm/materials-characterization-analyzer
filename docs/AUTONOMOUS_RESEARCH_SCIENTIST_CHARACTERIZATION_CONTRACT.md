# Characterization Evidence Contract for the Autonomous Research Scientist Architecture

## System role

`materials-characterization-analyzer` is the **characterization evidence authority** inside the wider Autonomous Research Scientist Architecture. It is not the global research orchestrator.

`materials-data-analyzer` is the research orchestrator and evidence consumer. It may use characterization outputs only through checksum-bound, independently validated handoff contracts.

The intended architecture is therefore:

```text
research objective / hypothesis
        |
        v
materials-data-analyzer
  - evidence graph
  - discrepancy diagnosis
  - next-evidence planning
  - authorization boundary
  - typed action execution
  - authenticated transition
        |
        | characterization evidence request / accepted bundle
        v
materials-characterization-analyzer
  - raw representation and acquisition audit
  - calibration / method validation
  - SEM / XRD / EDS / TEM / SAED / Raman / XPS / FTIR / thermal analysis
  - scientific evidence ladder L0-L8
  - checksum-bound feature + context handoff
        |
        v
independently validated characterization evidence state
        |
        v
materials-data-analyzer recursive research loop
```

The repositories remain separate authorities. The integration boundary is a versioned evidence contract, not shared mutable state and not direct trust in producer-authored summaries.

## L0-L8 handoff extension

A handoff bundle may optionally contain `scientific_evidence_ladder` while retaining the existing schema-1.0 bundle format. Legacy bundles remain valid without this field.

The ladder assessment is generated by the existing monotonic L0-L8 evaluator:

- L0 software integration
- L1 raw representation identity
- L2 acquisition provenance integrity
- L3 instrument calibration validity
- L4 method / algorithm validation
- L5 material-domain validation
- L6 independent external validation
- L7 replicated multisource support
- L8 engineering decision readiness

A higher level cannot be `Supported` unless every lower level is also `Supported`.

## Independent replay requirement

The handoff validator does not trust the producer-authored ladder summary. It:

1. checksum- and size-verifies the bound assessment file;
2. reads the assessment declaration;
3. re-runs the deterministic L0-L8 evaluator;
4. requires the full assessment to match that replay exactly;
5. requires `scientific_status_promoted=false`;
6. requires `downstream_use_authorized=false`;
7. requires the declaration ID to equal the handoff `case_id`;
8. requires source bindings for the exact handoff `source_manifest`, `analysis_manifest`, and `comparability_matrix` file SHA-256 values;
9. requires the declared modality to be represented by the bundle instruments.

This prevents a valid but unrelated assessment from being substituted wholesale for the bundle's own scientific context.

## Scientific boundary

The evidence ladder is **not new empirical evidence**. It is a provenance-bound statement of evidence maturity and unresolved blockers.

In particular, the ladder does not by itself establish:

- physical-aliquot identity;
- cross-modal scientific comparability;
- causality;
- target-material validity when only proxy materials are available;
- independent validation;
- multisource replication;
- engineering release readiness;
- predictive, causal, or engineering downstream-use authorization.

A first blocking level such as `L6_independent_external_validation` is an explicit request for more evidence, not permission to infer that the missing evidence exists.

## Consumer expectation

The orchestrator should independently validate the same contract without importing `mca` as a runtime dependency. It should convert `first_blocking_level` into a deterministic next-evidence requirement while preserving the ladder's declaration SHA, assessment SHA, source bindings, subject, and no-promotion flags.

This makes characterization a first-class evidence provider to the recursive research loop rather than a detached analysis utility.
